# Example 2: Professional Career Transition

## Scenario
A working professional wants to transition into data engineering. They have 5 hours per week and 6 months to build foundational skills while maintaining their current job.

## Input

```
I want to transition into data engineering. I'm currently working in operations
and have some basic SQL knowledge. I can dedicate about 5 hours per week, and
I have 6 months before I want to start applying for jobs. I learn best with
hands-on projects. I have a limited budget for paid courses.
```

## Expected Output Highlights

```markdown
# Personalized Learning Path — Data Engineering Career Transition

## 1. Learner Profile Summary

- **Goal**: Transition to data engineering role within 6 months
- **Current Level**: Basic SQL, operations background, limited technical skills
- **Time Budget**: 5 hours/week for 24 weeks (120 hours total)
- **Deadline**: 6 months before job applications begin
- **Modality**: Hands-on projects preferred
- **Constraints**: Limited budget for paid courses, studying while working

## 2. Learning Frameworks Applied

### Anchor Frameworks

**Backward Design** — All objectives map to data engineering job requirements

**Bloom's Taxonomy** — Progress from Understand (concepts) to Apply (projects) to Create (portfolio)

### Additional Frameworks

**Deliberate Practice** — Hands-on projects with iterative improvement and feedback

**Mastery Learning** — Build portfolio demonstrating mastery before job applications

**Spaced Repetition** — Maintain skills across 6-month timeline

**Self-Determination Theory** — Support autonomy and motivation during long-term transition

**Learning Objective**: [Apply] Write Python scripts for data manipulation tasks.

**Formative Assessment**: Complete Python data manipulation exercise

### Month 2: SQL & Database Fundamentals

- Advanced SQL (10 hours)

**Formative Assessment**: Database design + query optimization task
**Hours**: 20
```
